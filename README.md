# OxaSmash

Proof of concept for a smash like game inspired by John Wick.

A gun-fu platform fighter for the browser. Shoot to build up damage, hit to send people flying, stay out of the storm.
Play solo against bots, up to four on one screen, or online (up to six, on the game server) with friends using a 5-letter room code.

## Run it

```sh
npm install
npm run dev      # http://localhost:5173, reloads as you edit
npm run server   # the game server for online rooms (port 8787; the dev page reaches it at /ws)
npm test         # rule and server tests (no browser needed); BOT_TESTS=1 also plays full bot matches
npm run build    # static files in dist/ (the game server serves them too)
```

`../Server.cmd start` runs both the dev page and the game server.

The build uses relative paths, so `dist/` works from a subfolder such as `esjotace.github.io/oxasmash/`.

## How it's put together

| Folder | What lives there |
|---|---|
| `src/sim/` | The game rules: movement, weapons, melee, cover, doorways, storm, stocks. Plain JS, no Phaser. Runs in fixed 1/60 s ticks. |
| `src/bots/` | Bots. They read the world and return the same input a player would. |
| `src/net/` | The page's side of online rooms (a WebSocket to the game server), names and room codes, and the honor duel rules (`duels.js`, shared with the server). |
| `server/` | The game server (Node): online rooms over WebSockets, each running its own matches with the same rules code. |
| `src/game/` | Phaser: the match scene, keyboard/mouse controls, drawing, effects and the DOS-style word font. |
| `src/main.js` | Menus, lobby and results (plain HTML), and starting matches. |
| `public/art/` | Game art. The game uses an image here automatically when the name matches, and falls back to placeholder shapes otherwise. |
| `tests/` | Vitest tests for the rules, bots, duels and the game server's rooms. |
| `docs/` | `CREDITS.md` (where the art comes from, and its terms), `ITEMS.md` (every weapon and item's stats, generated by `npm run items`), `sounds.md`. |
| `tools/` | Python art tools (need Pillow): shrink an image to a sprite (`make_sprite.py`), cut a building into kit pieces (`slice_kit.py`), preview a kit layout (`compose_kit.py`), lit-window overlays (`window_lights.py`), side-by-side comparisons (`contact_sheet.py`). |

Outside this folder (local only, never uploaded): `../Assets/` holds the asset packs as downloaded (their licenses don't allow redistributing them; only the pieces the game uses are copied into `public/art/`), and `../workshop/art-source/` the art sources (`source/` raw images, `kits/` modular building pieces). `../Server.cmd` starts and stops the dev servers.

Tuning lives in `src/sim/constants.js` (movement, weapons, melee weapons, block, doors, barrels, storm, pickups) and the stage layout in `src/sim/stage.js`.

### Online play

The game server runs every online match: players send only their inputs, and it sends the game state back about 30 times a second; each browser draws it slightly in the past so it looks smooth. Whoever makes a room owns it (rules, bots, starting matches); if they leave, the next person takes over and the room carries on. Rooms hold up to 6 players, people and bots, and up to 6 more watching, who take a seat when one opens up, in the order they came.

### Putting it online (a VPS)

On a Linux VPS with Node.js 20 or newer:

```sh
git clone https://github.com/esjotace/OxaSmash.git && cd OxaSmash
npm ci && npm run build
PORT=8787 npm run server     # serves the game and the rooms; keep it running with systemd or pm2
```

Browsers need HTTPS for a page on GitHub Pages (or anywhere with https) to talk to the server, so put a web server with a certificate in front, e.g. Caddy with a domain pointed at the VPS:

```
game.example.com {
    reverse_proxy localhost:8787
}
```

Then the game is at `https://game.example.com`, rooms included. To keep the page on GitHub Pages instead, build it with the server's address: `VITE_SERVER_URL=wss://game.example.com/ws npm run build`, and publish `dist/`.

### Docker

Images are published as `esjotace/oxasmash`:

- `:latest`: the most recent build, overwritten on every release.
- `:v1`, `:v2`, …: milestone versions, created only when a bigger feature set is ready.

The image builds the page and runs the game server on port 8787 inside the container (page, rooms at `/ws`, `/health`, `/version`). Locally: `docker build -t esjotace/oxasmash:latest .` then `docker run -p 8787:8787 esjotace/oxasmash:latest` and open http://localhost:8787.

**On the droplet** (Docker installed): copy [docker-compose.yml](docker-compose.yml) to a folder and run `docker compose up -d`. The game listens on host port **8060**; point an nginx proxy host at it with **WebSocket support on**. The compose file has the Nginx Proxy Manager settings and a plain nginx `location` block. Update with `docker compose pull && docker compose up -d`. Rooms live in memory: restarting the container ends any match in progress.

**Releasing** (from this folder, signed in with `docker login`):

```bash
# every release: rebuild and overwrite latest (VERSION = the current milestone)
docker build --platform linux/amd64 --build-arg VERSION=v1 --build-arg BUILD="$(date -u '+%Y-%m-%d %H:%M UTC')" -t esjotace/oxasmash:latest .
docker push esjotace/oxasmash:latest
# milestone only: build with the new version so the label matches, tag it too, push both
docker build --platform linux/amd64 --build-arg VERSION=v2 --build-arg BUILD="$(date -u '+%Y-%m-%d %H:%M UTC')" -t esjotace/oxasmash:v2 -t esjotace/oxasmash:latest .
docker push esjotace/oxasmash:v2 && docker push esjotace/oxasmash:latest
```

`VERSION` (the newest milestone) and `BUILD` (a timestamp) show in the corner of the menu, at `/version` and in the server log at startup, so you can tell which build is deployed.
