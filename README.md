# OxaSmash

Proof of concept for a smash like game inspired by John Wick.

A gun-fu platform fighter for the browser. Shoot to build up damage, hit to send people flying, stay out of the storm.
Play solo against bots, two players on one keyboard, or online with friends using a 5-letter room code.

## Run it

```sh
npm install
npm run dev      # http://localhost:5173, reloads as you edit
npm test         # rule tests (no browser needed); BOT_TESTS=1 also plays full bot matches
npm run build    # static files in dist/, ready for any static host
```

The build uses relative paths, so `dist/` works from a subfolder such as `esjotace.github.io/oxasmash/`.

## How it's put together

| Folder | What lives there |
|---|---|
| `src/sim/` | The game rules: movement, weapons, melee, cover, doorways, storm, stocks. Plain JS, no Phaser. Runs in fixed 1/60 s ticks. |
| `src/bots/` | Bots. They read the world and return the same input a player would. |
| `src/net/` | Online rooms with PeerJS (WebRTC). The room code is the host's peer id. |
| `src/game/` | Phaser: the match scene, keyboard/mouse controls, drawing, effects and the DOS-style word font. |
| `src/main.js` | Menus, lobby and results (plain HTML), and starting matches. |
| `public/art/` | Game art. The game uses an image here automatically when the name matches, and falls back to placeholder shapes otherwise. |
| `tests/` | Vitest tests for the rules and bots. |
| `docs/` | `CREDITS.md` (where the art comes from, and its terms), `ITEMS.md` (every weapon and item's stats, generated by `npm run items`), `sounds.md`. |
| `tools/` | Python art tools (need Pillow): shrink an image to a sprite (`make_sprite.py`), cut a building into kit pieces (`slice_kit.py`), preview a kit layout (`compose_kit.py`), lit-window overlays (`window_lights.py`), side-by-side comparisons (`contact_sheet.py`). |

Outside this folder (local only, never uploaded): `../Assets/` holds the asset packs as downloaded (their licenses don't allow redistributing them; only the pieces the game uses are copied into `public/art/`), and `../workshop/art-source/` the art sources (`source/` raw images, `kits/` modular building pieces). `../Server.cmd` starts and stops the dev server.

Tuning lives in `src/sim/constants.js` (movement, weapons, melee weapons, block, doors, barrels, storm, pickups) and the stage layout in `src/sim/stage.js`.

### Online play

The host's browser runs the match. Guests send only their inputs; the host sends the game state back about 30 times a second and guests draw it slightly in the past so it looks smooth. PeerJS's free public server only introduces the browsers to each other, then traffic goes directly between players.

Limits to know about:
- If the host leaves, the match ends for everyone.
- Guests feel their own round-trip delay on their inputs (fine with friends nearby; noticeable across continents).
- Some strict networks (some mobile carriers, office Wi-Fi) block direct connections. Fixing that needs a TURN relay server.
- The free PeerJS server has no uptime guarantee.
